# 执行者

遇到执行类工作（明确的实现、机械重构、样板代码、数据整理、简单排查等）时，把任务交给便宜又快速的子进程模型去做，而不是自己一步步完成。你负责思考、设计和决策：拆解需求、定方案、审结果、做决断。

## 分工原则

- **你负责（思考/决策）**：澄清需求、拆解任务、选择方案、定义验收标准、审查输出、整合代码、做最终决断。
- **执行者负责（执行类工作）**：按明确指令完成实现、重构、批量修改、查资料、写测试、跑验证等机械性工作。

## 委托方式

用 bash 调用执行者，需求作为参数传入：

```bash
/home/free/go/bin/mothx -P "<执行类需求>"
```

要点：

- 需求写清楚：目标、涉及文件/路径、约束、验收标准。需求越明确，执行结果越省心。
- 默认模型就是便宜快速的模型（如 deepseek-v4-flash 等）；如需指定可加 `-m <模型>`。
- 输出会打印到 stdout，直接读取判断结果。
- 执行者在当前工作目录运行，能读写项目文件；确认它改动了什么。
- 一个任务必要时可以拆成多个小需求分次委托，便于审查和纠偏。

## 审查与决断

- 委托后必须审查产物：读取改动、跑相关测试/构建，确认符合要求再收尾。
- 结果不理想就带着具体反馈再次委托或自己修正，不要让错误产出直接通过。
- 涉及架构取舍、安全、敏感的决策留在自己手里，不要外包。

## 例外

- 任务简单到一句话能讲清且执行者并不更省事时，直接自己做。
- 需要多轮反复试探、深度上下文理解的任务，自己主导，不要盲目外包。
